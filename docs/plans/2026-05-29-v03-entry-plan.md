## 1. Goal — the S1 anchor

v0.3 delivers **S1**, the first flagship scene: **4096 Unitree Go2 running PPO locomotion on a single RTX 4090 at
sub-millisecond per env-step.** It anchors the throughput story (large-scale parallel sim for RL training) and lays the
Python/PyTorch surface that v0.5 fills with real differentiable simulation.

## 2. v0.3 Exit Criteria — no partial credit (§5.2)

Items 1–6 are the master plan **§7 v0.3 exit criteria** (verbatim, lines 906–911). Item 7 is **not** in §7; it is the
§5.1 *rhythm* requirement, which the Phase 4 spec (`v03-p04`) folds into its exit gate — recorded here so closure is
not declared without it.

1. **Step time < 1 ms per env-step on RTX 4090.**
2. **Energy drift < 2 % over 1000 steps.**
3. **4096-env Go2 PPO converges to stable walking gait.**
4. **PyTorch `autograd.Function` skeleton wired** (diff-sim *not* active — that is v0.5).
5. **V1 oracle for Featherstone fully passing** (carry-forward from v0.1; no regression).
6. **Demo: 4096-env Go2 locomotion video.**
7. *(§5.1 rhythm, not §7)* **Quarterly external output published** (blog / arXiv / talk).

## 4. Phase Sequence (strict linear dependency)

```
v0.1 CLOSED ─► Phase 1 (Perf) ─► Phase 2 (PyTorch skeleton) ─► Phase 3 (RL integration) ─► Phase 4 (PPO + EXIT)
```

Each phase is its own gate; downstream phases must not start until the upstream gate locks.

### Phase 1 — Performance Baseline + 4096-env Optimization
*Spec: `v03-p01-perf-baseline-and-optimization.md` · Blocks: Phase 4 (and effectively all downstream perf claims)*

- **Goal:** establish a hard RTX-4090 baseline for 4096-env Go2 and optimize to **< 1 ms/step**.
- **Deliverables:** in-engine perf timing (`src/core/perf/timing.*`, `perf_recorder.*`), perf sweep + regression tools
  (`tools/perf/run_perf_baseline.py`, `compare_perf_runs.py`), gate test `tests/perf/test_go2_4096env_step_time.cpp`,
  and `docs/architecture/perf-budget.md`. Hot-spot tuning in `row_solver.cu`, `featherstone_aba.cu`,
  `contact_generation.cu`, `cuda_batched_world.cu`. Expose **D1/D2 determinism toggle in the C ABI**.
- **Exit:** timing infra + CI per-kernel logs; documented baseline; **< 1000 µs gate test passes on RTX 4090**;
  D1/D2 toggle exposed; V1+V2 still pass.
- **Key risk:** if an optimization breaks D1 determinism, **reject it**; fall back to D2 for *training mode only*.

### Phase 2 — PyTorch `autograd.Function` Skeleton + nanobind Binding
*Spec: `v03-p02-pytorch-autograd-skeleton.md` · Prereq: Phase 1 gate + v0.1 C ABI · Blocks: Phase 3*

- **Goal:** zero-copy Python surface with a **forward-only** `autograd.Function` whose API is *locked* so v0.5 drops in
  the adjoint without redesign.
- **Deliverables:** `python/nuka/**` package (World/Device/autograd/dlpack adapters), nanobind C++ binding
  (`python/src/binding*.cpp`, `dlpack_utils.*`), build glue (`pyproject.toml`, scikit-build-core), Python tests
  (create/step, DLPack zero-copy, forward-only autograd, caller stream).
- **Exit:** `pip install nuka` wheel works; DLPack zero-copy proven (device-ptr match); PyTorch CUDA stream usable as
  engine stream; `autograd.Function` skeleton present (**backward returns zero grads in v0.3**); tests pass.
- **Note:** no real diff-sim, no JAX — both are v0.5.

### Phase 3 — RL Training Integration + Isaac Lab Adapter Stub
*Spec: `v03-p03-rl-training-integration.md` · Prereq: Phase 2 · Blocks: Phase 4*

- **Goal:** plumb the engine into a real RL loop (gym vectorized env + minimal Isaac Lab compat) for 4096-env PPO.
- **Deliverables:** `python/nuka/gym/**` (`NukaGymEnv`), `python/nuka/isaaclab_compat/**` (ManagerBasedRLEnv + managers),
  `python/nuka/tasks/go2_locomotion.py`, `examples/training/train_go2_ppo.py`, and **C ABI action/observation buffer
  views** (`nuka_world_get_action_buffer_view` / `…_observation_buffer_view`).
- **Go2 spaces:** observation **48-dim** (12 q + 12 qd + 3 lin-vel + 3 ang-vel + 3 gravity + 3 cmd-vel + 12 last-action),
  action **12-dim** (joint position targets), **4096** envs.
- **Exit:** action/obs views in C ABI; `NukaGymEnv` works with rl_games/SB3/SKRL; minimal `ManagerBasedRLEnv`;
  Go2 PPO task defined; training script *launches and begins training* (convergence is Phase 4); smoke tests pass.

### Phase 4 — Go2 PPO 4096-env Training + v0.3 Exit Demo
*Spec: `v03-p04-go2-ppo-4096-demo.md` · Prereq: Phases 1–3 · Gate: **v0.3 CLOSE***

- **Goal:** train 4096-env Go2 PPO to convergence and produce the v0.3 exit artifacts.
- **Deliverables:** finalized `go2_locomotion.usda` + `go2_ppo_cfg.yaml`, demo/replay/visualize scripts + `render_video.sh`
  (PPM→MP4), smoke-train + full-RL-loop perf regression tests, `docs/architecture/go2-locomotion-demo.md`, and the
  quarterly external output (`docs/plans/2026-XX-XX-v03-retrospective.md`).
- **PPO config (exact):** num_actors 4096, γ 0.99, τ 0.95, lr 3e-4, e_clip 0.2, horizon 24, minibatch 32768,
  mini_epochs 5, max_epochs 1500, save_frequency 100. **Wall time ≈ 6–10 h on RTX 4090.**
- **Convergence checkpoints:** ep50 reward > 0; ep200 visible gait; ep500 cmd-vel-x within 20 %; ep1000 within 5 %;
  ep1500 stable across **±2 m/s**.
- **Exit = v0.3 CLOSE:** all 6 §7 criteria green + the §5.1 quarterly external output; D1 determinism bit-exact across
  replayed rollouts; demo video (16-env grid, 30 fps).

## 5. Performance Budget (Phase 1 target — sums to the 1 ms gate, on RTX 4090 @ 4096 envs)

| Stage | Budget (µs) |
| --- | ---: |
| Contact generation (broadphase SAP + narrow-phase) | 150 |
| Featherstone ABA (3 passes, warp-per-articulation) | 80 |
| Row builder (per-env prefix-sum, no atomics) | 50 |
| Graph-coloring scheduler (cached unless topology changes) | 20 |
| Row solver (PGS ~10 iters) — dominant | 500 |
| Integrator (symplectic Euler) | 30 |
| V2 invariant sampling (every 16 steps) | 50 |
| Buffer management | 20 |
| Headroom (stalls, launch overhead, jitter) | 100 |
| **Total** | **1000** |

RL-loop overhead budget (Phase 3): **< 1.2 ms** (1 ms physics + 20 % headroom).

## 6. Risks (master plan §8 + per-phase)

- 🟡 **D1 determinism vs the < 1 ms bar** (§8, Medium / v0.3-gate). Mitigation: D2 weak mode for training, D1 for
  oracle/debug; reject any optimization that breaks D1.
- 🟡 **Gate hardware gap confirmed; handling resolved (§7).** Dev box is 2× RTX 4000 Ada (~3× below the §7 4090) so the
  absolute gate is not reachable here. **Resolution (owner, 2026-05-29):** this box is the dev/optimization platform
  (records RTX-4000-Ada baseline); the owner validates on an **RTX 5080** against a supplementary v0.3-doc target of
  **< 1.3 ms/env-step @ 4096** (relative-derived), with Nsight profiling there. The §7 4090 gate is unchanged/protected.
  This session implements the parameterized gate test; the 5080 perf run is a deferred hand-off.
- 🟢 **PyTorch/Isaac Lab API churn** — mitigated by binding to a minimal, locked compat subset (Phase 2/3), not the full
  Isaac Lab surface.
- 🟢 **PPO non-convergence / reward shaping** — staged convergence checkpoints (ep50/200/500/1000/1500) give early
  signal before the full 6–10 h run.
- ⏳ **Self-written sparse solver** — out of scope for v0.3; cuDSS remains default through v0.5 (§8 reserve).

## 7. Toolchain & Hardware Assumptions

- **Formal perf gate (protected):** master-plan §7 = **< 1 ms/env-step @ 4096 on RTX 4090**. Unchanged here — only the
  owner may revise §7. No RTX 4090 is available to this project.
- **Dev/optimization platform (this box):** **2× NVIDIA RTX 4000 Ada Generation** (sm_89, ~20 GiB/ECC-off, 48 SMs,
  360 GB/s), confirmed 2026-05-29 via `cudaGetDeviceProperties` + `/proc/driver/nvidia/gpus` (`nvidia-smi` NVML mismatch
  persists; CUDA 12.8 runtime functional). ~3× below a 4090 on FP32 and bandwidth, so the absolute gate is **not
  reachable here** (a 4090-< 1 ms workload ≈ 2.8–3.1 ms on this card). **Role:** all Phase-1 instrumentation, profiling
  (in-engine timers), and kernel optimization run here; `baseline.json` records RTX-4000-Ada numbers as the relative
  regression reference. Standing constraint holds: **do not change drivers/system**.
- **Validation platform (owner, deferred):** **RTX 5080** (Blackwell sm_120, 16 GiB GDDR7, 960 GB/s, ~84 SMs,
  ~56 TFLOPS FP32). The owner runs the final perf validation + Nsight (`ncu`/`nsys`) profiling there; this session
  *implements* the gate test and leaves the perf run as a hand-off. **v0.3-doc validation target (relative, owner-set
  2026-05-29):** **< 1.3 ms/env-step @ 4096 on RTX 5080.** Derivation: 5080 ≈ 0.68× a 4090 on FP32 and ≈ 0.95× on
  bandwidth; the 1000 µs 4090 budget is dominated by the (bandwidth-leaning) PGS row solver + contact gen, so a
  budget-weighted blend → ×1.2–1.3 → 1300 µs. This is a **supplementary v0.3-doc target, not a §7 change**; the §7 4090
  gate stays the formal protected gate. VRAM note: 5080 has 16 GiB — confirm 4096-env Go2 fits there during validation.
- **Profiling reality (this box):** Nsight is limited — no `nsys`; only `ncu 2021.1` (pre-Ada, unreliable for sm_89).
  In-engine CUDA-event timers are the primary per-kernel measurement path here; full Nsight profiling happens on the 5080.
- **Build:** C++20, CUDA 12+, CMake; Python via scikit-build-core + `pyproject.toml`.
- **Python stack:** Python 3.10+, PyTorch 2.4+, nanobind 2.x, DLPack 1.x, gymnasium 0.29+, rl_games 1.6+ (or SKRL/SB3).
- **Profiling:** Nsight Compute (kernels) + Nsight Systems (timeline).
- **Rendering:** reuse the v0.1 render path → PPM → MP4 via ffmpeg.
