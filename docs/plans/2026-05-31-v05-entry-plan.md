## 3. Cross-cutting risks the specs under-state (READ BEFORE p01)

**R1 — Adjoint validation has TWO distinct targets; generated forwards are stubs.**
The generated `*_forward.cu` are linkable **stubs**; real physics is the hand-written engine. So:
- **p01 (row-class FD):** generate each row-class **forward-update *and* its adjoint as a matched analytic pair** and FD-test the *pair in isolation* (perturb the row's inputs, compare numerical vs analytical Jacobian). This is self-contained and needs no engine wiring — it proves the *math* of each row class.
- **p04/p05 (end-to-end FD):** the `torch.autograd` FD check differentiates the **real engine step pipeline**. That requires the *connective* adjoints — **ABA 3-pass reverse, CRBA(mass), velocity/position integration, FK link-pose, effective-mass `1/(J·M⁻¹·Jᵀ)`, contact detection** — most of which are **NOT row classes** and so are *not* covered by "row-class adjoint codegen." These live in p02's `backward_runner` as hand-written-but-D1 adjoint steps (codegen-emitted where a row class maps cleanly; hand-written for ABA/CRBA/integration). **This connective tissue is the real bulk of v0.5 and the spec's biggest blind spot — sequence it explicitly in p02, not as a p01 afterthought.**

**R2 — Tape replay is NOT bit-exact unless λ warm-start is in the checkpoint.**
PGS runs a **fixed 48 iterations with no early-out**, and λ warm-start **persists across steps**, so the solve result is a deterministic function of (start-λ, rows). The `Reset()` snapshot set (base_pose/link_vel/q/qdot) **omits λ**. ⇒ p02 checkpoints **must also snapshot the warm-start λ buffer** at checkpoint boundaries, or replay from a checkpoint diverges from the original forward and the `ReplayBitExact` test fails. Add λ to the `Checkpoint` struct.

**R3 — IFT-at-convergence is an *approximation* of fixed-48 PGS; verify before relying on it.**
IFT (p03) backprops through the *converged* KKT. The forward never converges to a residual tol — it stops at 48 iters. So tape-backward (steps through the 48 iters) and IFT-backward (assumes convergence) agree **only if 48 iters ≈ converged on the test scene**. De-risk: (a) the `IftVsTape` agreement test must run on a scene where PGS is near-converged at 48; (b) prefer the **exact direct-dynamics adjoint** (ABA/CRBA) for the demo spine (§4), using IFT for contact only where convergence is demonstrated. Document the approximation honestly; don't oversell IFT exactness on the contact branch.

**R4 — No deterministic reduction / device island / Eigen / `DeviceVector` / `WorldState`.**
CG builds its **own** per-env fixed-order tree reduction (small systems: ~12 DOF + few contacts per env → single-warp/block reduction is enough and D1). Block-Jacobi blocks = **per-articulation natural islands** (the engine already partitions contacts per articulation), NOT the host `RowColorPartitions`. Add **Eigen via FetchContent (test-only host)**. Map specs' `DeviceVector<T>` → `phi::Buffer` + `static_cast`; there is no `WorldState` struct — operate on `ArticulationDeviceBuffers`.

**R5 — `stop_grad_on_event` breaks a naive "adjoint vs FD" assert at events.**
2 of 4 row classes are `stop_grad_on_event`: at a stick→slip / contact transition, **numerical FD measures a real nonzero sensitivity** while the analytical adjoint **deliberately returns zero** (the β strategy). A blanket `max_rel_err < 1e-3` assertion **fails exactly at events by design.** The V3 harness must (a) generate comparison cases **away** from event boundaries, and (b) carry a **separate** "adjoint == 0 when event bit set" assertion. Design this in p01; don't discover it in CI.

**R6 — The D1 gate must extend to the backward pass.**
Today's two-run byte-exact gate covers forward `q`. The non-negotiable D1 contract must, post-v0.5, also cover **`grad_actions`, `grad_parameters`, and the CG solve output** (two-run `EXPECT_EQ`). Add these to the determinism harness as the diff-sim path lands. The CG `BitExactSameInputs` test (p03) is part of this.

**R7 — Verify JAX-GPU on THIS box EARLY (before p04 commits to it).**
The surveys confirmed torch cu124 but **never checked jaxlib**. jaxlib's CUDA wheel must match the installed driver/CUDA, and NVML is driver-broken on this box (memory). **Action: a 30-minute probe at the START of p04 (or end of p03)** — `pip install jax[cuda12]` (or matching local), run a trivial `jax.numpy` GPU op + `jax.grad`. If it can't run on-box, exit #4 closes **qualified** (custom_vjp implemented + tested wherever runnable, agreement test skipped-as-recorded like the v0.3 perf gate) rather than blocking the sprint. Decide at the probe.

**R8 — OSC's differentiable path couples Workstream C to p03.** Operational-space control needs the task-space inertia `Λ = (J·M⁻¹·Jᵀ)⁻¹` per env; its **adjoint is a matrix-inverse derivative** (`d(A⁻¹) = −A⁻¹·dA·A⁻¹`). Route it through the **p03 self-written solver** (or a small fixed-size per-env Cholesky), so OSC's *differentiable* path lands **after p03**. The OSC *forward* mode can ship earlier with the other modes; only its adjoint waits. Sequence accordingly — don't block C-fwd on p03.

**R9 — control-saturation clamps are stop-grad-like nonsmoothness (cf. R5).** The PD/torque/velocity **force-limit clamp** and the actuator-model **torque-speed envelope** are non-differentiable at saturation: FD measures the unsaturated slope, the analytical sub-gradient is zero (or the envelope slope) at the clamp. The per-mode FD harness must **compare away from saturation** and carry a **separate sub-gradient/zero-at-clamp assertion** — exactly the R5 away-from-event split, reused for control clamps.

## 4. THE PARAMETER-GRADIENT SPINE (exit-gate critical path — first-class workstream)

The exit demo (#7) recovers an unknown **link mass** by gradient descent — a gradient **w.r.t. a physics parameter**, *not* w.r.t. actions. The entire existing `autograd.py` skeleton is an **action-gradient** path; the mass path is a **different buffer and a different chain that nothing today provides.** This is the single most likely place v0.5 fails late. It cuts across all five phases and must be tracked as one spine:

```
p01  IR: declare WHICH parameters are differentiable (mass/inertia/friction/...) +
         CRBA/ABA mass-adjoint derivative rules (exact; direct dynamics, no convergence assumption)
  ↓
p02  tape backward emits grad_parameters (C ABI already RESERVES the slot:
         nuka_tape_backward(..., void* grad_parameters_out) — anticipated, unbuilt)
  ↓
p04  Python surface takes mass as a TENSOR input (the differentiable_step signature is UNLOCKED
         — free to add a params arg; the LOCKED surface is only step(world, actions))
  ↓
p05  runtime set_link_mass (NEW: mass lives in link_inertia, no C ABI/field today) + the demo
```

**What's missing today (all four are on the spine's critical path):**
- (a) a **runtime mass/inertia write** — `nuka_world_set_link_mass` (or a writable `LINK_INERTIA` field) + binding. Mass is in `link_inertia`; there is no setter.
- (b) a **parameter-gradient buffer** (`grad_parameters`) + DLPack export (mirrors the action-grad buffer; the `nuka_tape_backward` slot exists).
- (c) the **CRBA/ABA adjoint** depositing `dL/d(mass)` — the exact direct-dynamics chain (no PGS-convergence assumption), which is also the cleanest, lowest-risk gradient in the engine.
- (d) the **Python param-tensor input** so `mass_param.grad` populates.

**The p05 demo as written is broken — fix it in the plan.** The spec's loop does:
```python
world.set_link_mass("front_left_thigh", mass_param.item())   # .item() SEVERS the graph
loss.backward()                                              # → mass_param.grad is None
optimizer.step()                                            # no-op; never converges
```
The correct surface passes `mass_param` as a **tensor** through `differentiable_step(world, tape, actions, params=mass_param)`, whose `backward` reads `grad_parameters_out` from the tape and routes it to `mass_param.grad`. Bake this corrected contract into p04/p05.

**Why this is also the lowest-risk gradient (lean into it):** mass flows CRBA→`M`→ **both** (i) ABA accelerations — *direct, exact adjoint, no convergence assumption* — and (ii) contact effective-mass `1/(J·M⁻¹·Jᵀ)` → PGS (the R3 precision risk). **De-risk the exit demo by designing the system-ID test trajectory contact-light**, so mass sensitivity flows mainly through the exact direct-dynamics adjoint. Verify fixed-48 PGS ≈ converged on the demo scene before letting any contact-mass gradient onto the critical path. The exact direct-dynamics chain is the spine; the contact-mass branch is the precision risk to fence off.

## 4b. WORKSTREAM C — Control algorithms beyond PD (owner-added 2026-05-31; cross-cutting)

Owner directive: v0.5 ships control algorithms beyond the current PD position drive. Owner chose **进取档** (ambitious) scope + **differentiable & featured in the exit demo**. This is a first-class cross-cutting workstream like the §4 parameter-gradient spine; it threads p01→p05.

**Engine reality grounding the design (survey-confirmed):** PD is **hard-wired** in `ApplyPositionDrives` (`featherstone_aba.cu:741-770`, `tau = Kp·(target−q) − Kd·qdot`, force-clamped) — **no control-mode selector today**. But the model-based ingredients are **already computed every step on device**: mass matrix `M` + inverse `M⁻¹` (CRBA + LDLᵀ factor), bias `C+G` (ABA pass-2 `link_bias_force` + gravity in pass-3/integrator), chain Jacobians `J`. So computed-torque/OSC are **cheap reuse**, not new dynamics. Implicit joint damping (#43) is **orthogonal** to the control mode (a general viscous `C` folded into `M+dt·C`), so new modes inherit it unchanged.

**Scope (the 5 modes + PD):**
| Mode | Law | Cost | Adjoint |
|---|---|---|---|
| PD position (existing) | `τ = Kp·(q*−q) − Kd·q̇`, clamped | — | trivial (gains differentiable, §4) |
| **Direct torque / effort** | `τ = τ_in`, clamped | trivial | trivial (`dτ/dτ_in` = clamp mask) |
| **Velocity** | `τ = Kp_v·(q̇*−q̇)`, clamped | cheap | trivial (`dτ/dq̇*`, `dτ/dgain`) |
| **Computed-torque / inverse-dynamics** | `τ = M(q̈* + Kp·e + Kd·ė) + C·q̇ + G` (gravity-comp = sub-case) | cheap (reuse `M`, `C+G`) | chain through CRBA/ABA adjoints (= §4 spine machinery) |
| **Operational-space (OSC)** | `τ = Jᵀ(Λ(ẍ* + Kp·e_x + Kd·ė_x) + …)`, `Λ=(J·M⁻¹·Jᵀ)⁻¹` | moderate (reuse `J`, `M⁻¹`; small per-env dense `Λ⁻¹`) | matrix-inverse-derivative on `Λ` → route through p03 self-written solver / small Cholesky (**R8**) |
| **Actuator model** | DC-motor torque-speed envelope (effort limit `= f(q̇)`); optional learned actuator-net (MLP) | cheap (envelope) / moderate (net) | envelope: piecewise (R9); net: standard MLP adjoint, ties to p04 sim2real |

**Phase threading:**
- **C-fwd (engine — FIRST work of the sprint, a p01 *prelude*):** `enum class ControlMode{PDPosition=0,Torque,Velocity,ComputedTorque,Osc,Actuator}` + a **stage-1 `ApplyDrives(mode)` dispatcher** + per-mode sub-kernels in a **new `src/runtime/articulation/articulation_drives.cu`**. New C ABI: `control_mode` selector (in `nuka_world_desc_t` and/or per-step params) + new fields `TORQUE_INPUT`, `VELOCITY_TARGET`, `TASK_TARGET` (OSC). **Default `PDPosition` byte-identical** (gate new logic behind `mode != PDPosition` or split kernels; the `go2_stand_5s` golden + determinism ctest must not move). Lands early because p01's adjoint codegen must cover **all** modes.
- **C-adj (p01):** each mode's adjoint, FD-validated (`<1e-3`, away from force-clamp per R9). **Gains (Kp/Kd/Kp_v/force-limit) become differentiable parameters** — they join mass on the §4 parameter-gradient spine (so system-ID can recover a *gain*, not just a mass).
- **C-abi/py (p02/p04):** mode selector + the new target/torque fields wired through tape + `differentiable_step(world, tape, actions, *, control_mode=…, params=…)` (the unlocked surface). OSC's differentiable `Λ⁻¹` path lands **after p03** (R8).
- **C-demo (p05):** the exit demo gets a **non-PD variant** — e.g. system-ID under **torque control**, or **recover a control gain (Kp)** by gradient descent (now a differentiable param). Enriches the diff-sim narrative beyond mass-recovery.
- **C-test:** per-mode D1 two-run byte-exact; default-PD golden byte-identical (the hard gate); per-mode adjoint FD; computed-torque/OSC sanity vs an analytical reference; actuator-model limit/energy test.

**New risks folded into §3:** **R8** (OSC `Λ⁻¹` adjoint couples Workstream C to the p03 solver — sequence OSC's differentiable path after p03; forward OSC can land earlier), **R9** (force-limit / torque-speed clamp is a stop-grad-like nonsmoothness like R5 — FD-compare away from saturation + assert sub-gradient at the clamp).
