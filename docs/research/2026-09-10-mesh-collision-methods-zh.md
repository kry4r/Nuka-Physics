# 三角表面碰撞与 GPU 凸分解：调研和候选设计

更新：2026-09-10。本文区分公开方法、可迁移的算法思想、Nuka 的候选设计和本机实测；论文中的加速比不作为 Nuka 的性能结果。

## 结论与实施方向

原始三角面保留为几何依据。刚体局部网格可共享只读 BVH；变形薄面需要更新包围盒、点面/边边接触和 CCD。凸分解、面简化、距离场及硬件光追是不同的加速手段，选择取决于完整查询成本、误差和拓扑，不能默认把凹网格变成一个凸体。

按用户补充，调研以算法思想及并行化潜力为主。CPU 实现可以重组为 GPU 批量计算；没有现成 CUDA 代码不构成淘汰理由。当前值得推进的组合为：

1. 真实三角面 + 可更新的 GPU BVH，提供公共最近特征/重心坐标/符号契约。
2. 参考连续碰撞研究补齐候选和保守时间界，之后与共同质量响应、子步反馈接线。
3. 探索下述“误差驱动的并行半空间分解”。以原型判断其是否能减少反复构造凸包、网格封口和串行搜索的成本。
4. 稀疏距离界和凸覆盖首先可作保守筛选；采用近似面作最终碰撞体时，必须显式声明误差并重新验收物理质量。

## 候选方法：误差驱动的并行半空间分解

这是基于公开思想独立设计的候选，尚未证明学术新颖性或性能领先。区别待验证在于：共享原网格距离层次、延迟实化裁剪结果、区分可收紧的外包络误差和必须切分的凹性，以及复用分块间的误差证据。

### 1. 输入与输出

输入为明确表示实体的闭合三角网格 `S`、世界单位误差 `epsilon > 0`、资源预算和确定性策略。开放薄面继续使用双面三角表示；只有作者明确给出厚度并形成实体时才进入体积凸分解。自交或不明确的实体语义必须单独处理。

输出为正体积闭合凸多面体 `P_i`、支撑/裁剪来源、原始几何身份、误差证据及完成状态。目标为：

`S ⊆ U = union(P_i) ⊆ S ⊕ ball(epsilon)`。

这同时要求无漏覆盖和外扩受限。开口中距离原实体超过 `epsilon` 的点不得被填入；表面 Chamfer 小或总体积差小都不能替代这个条件。分块数不是全局最优保证，需与 CoACD 等方法在相同实际误差下比较。

### 2. 延迟构造与支撑查询

每个候选块维护半空间集合 `P={x: A*x<=b}`、活跃原始三角引用及距离层次节点引用；搜索期间不反复复制完整网格、封切口、重建 BVH。

对于正则闭实体，块内实体取 `R_P=closure(int(S)∩int(P))`，计算 `h(n)=sup(n·x, x∈R_P)`。这是实体交的正则化：只触及切面、没有邻近实体体积的残片不应撑大子块。完整的支撑候选包括：贡献于 `R_P` 边界的原三角裁剪多边形顶点，以及位于 `R_P` 内的 `P` 顶点。后者不可省略，否则完全处于实体内部的块会被误判为空；也不能只筛选原网格顶点，三角形与切面的交点可能才是极值。原型以共面方向和内侧探针处理边界，尚不构成浮点覆盖证明。

GPU 按活跃块和三角批次并行裁剪，方向归约共用裁剪结果。使用 prefix-sum/压缩数组管理变长输出，不规定某个场景或固定凸片顶点数。支持值必须向外保守扩张并附带数值界；不确定时保持原块，不能裁掉可能存在的物质。

### 3. 两类操作

距离层次产生一个位于候选块内、过量填充的见证点 `w`。

- 若某方向满足 `n·w > h(n)`，加入保守支撑平面，收紧包络而不增加凸片数。方向可来自最近特征、可见性冲突、现有面或几何主方向。
- 若现有候选方向无法有效收紧，则提出多张切面，批量评价子块的支撑界、剩余误差和预计查询工作量，再选定切面。方向尝试失败并不证明数学上不可分离，只能说明本次候选不足。

实测发现最近源三角面可能处于当前块之外，沿其法线继续二分会产生无效薄片；最近原表面的方向也不等于到块内实体凸包的分离方向。候选因此采用 GJK/Gilbert 的支撑单纯形思想，寻找 `conv(R_P)` 的分离平面。支撑距离给出下界，单纯形最近点给出上界；不能找到一点正间隙就停止，否则会不断加入几乎不收缩的平面。GJK、半空间裁剪和下述距离界均是已有数学工具，本设计的候选价值在于它们的调度、共享数据和 cook 契约，不能据此宣称发明了这些基本算法。

多个切面在 GPU 复用一次父块三角裁剪，分别计算子块支撑；候选打分使用误差采样和子块尺寸，仅决定搜索顺序。最终接纳仍检查完整候选体积。原型尚由 CPU 维护队列、求半空间顶点及选择切面，不是全 GPU cooking。

### 凸性冲突的进一步候选

VisACD 原文 §3 用顶点之间的外部可见边，按切面切断的边长总和评分；GPU OptiX 计算可见性，另外提高大平面的候选权重。其近似排序忽略新切口产生的可见边，不是完整体积误差证明；全顶点对的工作与存储也需要计入。本次据此产生的进一步设计是自适应的凸性冲突点集，而不是把全部顶点对直接搬到 GPU。

设支撑查询返回 `s_i∈R_P`，单纯形给出 `q=Σλ_i s_i, λ_i≥0, Σλ_i=1`。若 `d_S(q)>epsilon`，任何满足 `K⊆S⊕ball(epsilon)` 的凸块 `K` 都不能同时包含全部 `s_i`；否则由凸性 `q∈K`，产生矛盾。三维中至多四个点可表达这样的凸包内见证。由已查询的 `w` 可先用 `d_S(w)-|w-q|` 作下界，取得冲突而无需再做一次最近面查询。

这使分解可以在仍存在外包络误差时直接识别真正需要切分的块，避免先构造一个已经确定不能接纳的精细凸包。共享冲突记录在子块中复用；候选平面优先分离其支撑点，并用少量点的投影评分。两个点对应边冲突，三至四个点也能表达仅查边不足以解释的面内/体内凹腔。冲突用来决定切分，不能代替输出覆盖和整个体积的距离验收。

上述引理的前提是支撑点属于源实体且距离下界可靠；原型的浮点裁剪和查询仍未达到形式化认证。因此这是可验证的新组合候选，尚未确认文献新颖性或性能优势。当前对照表属于未加入冲突调度的 v6；后续结果独立记录，不能混作同一实现。

`P_minus=P∩{n·x<=t}` 与 `P_plus=P∩{n·x>=t}` 覆盖原块，内部不重叠。每个子块继续收紧和认证。最终才实化凸片顶点/面并做邻接合并；任何合并都重新检查同一误差条件。不能为追求更少凸片而放宽 `epsilon`。

### 4. 共享距离上下界

闭合实体的真实 signed distance 为 `d_S`。对中心 `c`、外接球半径 `r` 的空间单元 `Q`，若点查询含已证明的数值误差 `delta`，由 1-Lipschitz 性得到：

`d_S(c)-r-delta <= d_S(x) <= d_S(c)+r+delta, x∈Q`。

- 上界不超过 `epsilon` 时，该单元中候选块的部分满足外扩要求。
- 下界大于零时，该单元没有原实体；只有整个待丢弃区域获得此证明才能丢弃。
- 候选块内存在点的距离下界超过 `epsilon` 时，取得拒绝见证。
- 其余单元细分；预算耗尽返回未认证，不返回成功。

距离单元以稳定空间身份缓存，多个候选和子块复用查询值及界。整个候选体积需要检查，包括完全封闭的内部空腔。只认证外表面不充分。

另一个可复用上界来自固定源三角形 `T⊆S`：到凸集 `T` 的无符号距离是凸函数，故一个盒子的最大 `dist(x,T)` 不超过其八个顶点的最大距离；同时 `d_S(x)≤dist(x,T)`。将它与 Lipschitz 上界取较小值，可减少近表面单元因球界过松而反复细分。GPU 对单元并行计算，源三角形可取中心点的最近面；此选择影响界的松紧，不影响精确算术下的上界性质。浮点版本仍需单独的数值余量证明。

上述是不依赖设备的数学契约。现有浮点最近点和奇偶查询尚不自动提供形式化的 `delta`；原型的采样或经验误差余量只能给实验结果，不能标注为严格认证。生产接纳前需要稳健谓词、向外舍入或可核验的误差界。

### 5. 覆盖证明与终止

根块包含正则闭实体 `S`。精确算术下，每次支撑裁剪保留 `R_P`，平面两侧的正则实体交覆盖父块内的实体，仅丢弃已证为空的正则交，因此归纳得到 `S⊆U`。每个输出块完成体积距离认证后得到 `U⊆S⊕ball(epsilon)`。开放零厚面、退化实体及自交的实体语义不由此证明覆盖。

数值预算、最大输出容量和迭代预算均为显式资源限制。零进展、退化、内存不足或证据不够返回可读的未完成状态，不能用未认证凸包补齐输出。可用有界直径的空间细分提供进展，但它可能产生大量小片，须计入成本；不把这种终止手段的存在写成高效性证明。

## GPU 并行化及成本判断

| 工作 | 可复用的 CPU 思想 | GPU 组织与待测风险 |
| --- | --- | --- |
| 候选生成/筛选 | CoACD 多步前瞻、可见性冲突、几何启发式 | 活跃节点批量提交；候选分层筛选。改变搜索顺序是算法变化，要记录块数和实际误差 |
| 支撑与裁剪 | 半空间交、多边形裁剪、凸支撑函数 | 分块/三角/方向并行，变长结果用扫描分配；近退化切面和寄存器/全局 scratch 成本可能成为热点 |
| 误差搜索 | branch-and-bound、signed distance 的 Lipschitz 界 | 常驻 BVH、批量单元查询、共享层次与活跃队列；薄壁和极小误差可能使不确定单元数快速增长 |
| 凸片实化/合并 | 双表示、邻接图、外包络简化 | 接纳后延迟实化、互不冲突的合并并行执行；合并后的包络必须重验 |
| 碰撞运行时 | 层次包围、temporal coherence | 凸覆盖只作筛选时继续查询原三角面；BVH 更新/构建、候选数和最终 manifold 一起计时 |

设原始三角数为 `N`、活跃三角引用总量为 `R`、候选方向/切面工作量为 `C`、新增距离单元数为 `Q`。成本由裁剪和支撑的 `R×C`、BVH 距离查询及输出复杂度决定；最坏情况下不会自动成为线性算法。预期收益来自减少重复实化和查询复用，必须测出复用比例、GPU 完成时间、显存与分块数量才能判断。

## 验证与接入顺序

1. 先完成当前真实三角表面批次的生产验收。原失败和只启用速度求解时的柔顺压入数据保留，不作为加速分母。
2. 在 `out/`、`.nuka-runs/` 做有界原型：首先检验支撑查询是否包含裁剪交点与内部块顶点，再运行凹体、带孔实体及旋转版本。源码和参数可重放。
3. 对照 CoACD、V-HACD；比较相同输入的实际外扩/漏覆盖/孔洞和片数，报告 CPU 控制、GPU 计算、搬运、最终实化、总墙时和显存。阈值名称相同不代表质量相同。
4. 原型未通过的方向不接入生产。值得保留的候选再形成后端无关 cooking 接口，CUDA 实现留在 CUDA 目录；原始 TriMesh 查询始终保留。
5. 运行固定 robot-cloth-fluid、water pool/jelly 及公共 cook/world/reset/readout；涉及几何显示时包含渲染。性能结论使用五个独立进程并包含完整管线，不能以 cooking 或查询微基准代替端到端收益。
6. 接续全量耦合的插值端点、有限质量、子步闭环、自碰撞/CCD 和提袋/拧毛巾 demo。凸分解本身不完成柔体耦合。

## 本机原型证据与决定

决定：保留共享距离证据、裁剪复用、双向支撑分离这些方向；杯子分块数仍明显不如 CoACD，暂不将候选升为生产默认。下一步应处理分块/邻接合并、跨支撑查询复用、活跃三角压缩和 CPU 编排成本，并在旋转、真实资产和更细误差下检查覆盖。五进程、V-HACD、整场 cook 和接触运行时收益尚待采集；不以“原创”代替淘汰标准。

## 自动场景 cook 的交付契约

按用户最新要求，最终算法直接接入统一 cook：用户只提供场景，内部自动完成实体/开放面/变形面识别、设备能力选择、分解、缓存及模型上传。混合场景中的每个 collider 保留原始拓扑、局部变换、材料和实际物理 owner；实例共享只读几何。缓存身份包括算法版本、输入、尺度、误差和实体语义，并覆盖序列化、重新加载和 recook。

闭合实体的凸覆盖可先用于加速筛选，最终接触仍回到原始面；开放袋口/布料使用真实双面表面，不自动封口。未具备可靠包络证据的候选不能用于排除碰撞。自动分解资源不足时保留完整原三角表示及内部状态，不能漏 collider 或以未验收凸片返回成功。需要近似实体作最终 collider 时，另行明确几何契约并验收物理变化。

现有三角面 cook 和独立候选原型只是基础；自动分解尚未接入，不能据当前 `Auto` 的原面保留行为宣称完成用户要求。实现成熟后必须通过同一入口运行 cook→create→control→step→reset→readout/render，保持 multi-backend，不要求用户调用单独的 GPU 工具。
